# Пользовательские сценарии

**Проект:** Менеджер заметок. **Версия:** 1.0. **Дата:** 18.11.2026.

Актор всех пяти сценариев — владелец локальных заметок (текущий пользователь ОС). Отдельной серверной авторизации нет. CLI реализует ввод/вывод, сценарии — операции, хранилище — сохранение. Интерфейс не содержит бизнес-правил.

Уточнения контракта: ID — полный UUID4 вместо усечения 8 символов; даты — UTC ISO 8601. Пустой поиск в SC-003 является ошибкой (в отличие от практики №5). При редактировании None означает «не менять», явно пустая строка является ошибкой. Одновременная несогласованная запись нескольких процессов не поддерживается.

## Базовые требования проекта

| ID | Содержание |
|---|---|
| FR-001 / UR-001 | Создать заметку с заголовком и текстом; пользователь сохраняет новую запись. |
| FR-002 / UR-002 | Показать все заметки, новые сверху; пользователь выбирает запись. |
| FR-003 / UR-003 | Найти подстроку в заголовке/теле без учёта регистра; пользователь находит нужное. |
| FR-004 / UR-004 | Изменить поля существующей заметки; пользователь актуализирует запись. |
| FR-005 / UR-005 | Удалить существующую заметку; пользователь подтверждает удаление в CLI. |
| NFR-002 | При неуспешной записи прежние данные сохраняются; атомарность JSON/SQLite. |
| NFR-004 | Понятные русскоязычные ошибки предметной области без traceback в CLI. |

## SC-001: Добавление заметки

**User Story:** Как владелец заметок, я хочу сохранить новую заметку с заголовком и текстом, чтобы не потерять важную информацию.
**Актор:** Владелец заметок.
**Предусловие:** Пользователь запустил приложение.
**Триггер:** `note add`

### Основной поток
1. Система запрашивает заголовок; пользователь вводит 1–100 символов.
2. Система запрашивает тело; пользователь вводит 1–10000 символов.
3. Входные строки очищаются от пробелов по краям и проверяются.
4. Создаётся полный UUID4 и UTC-время создания/обновления.
5. Загружаются текущие заметки и сохраняется новый список атомарно.
6. Показывается подтверждение с ID.

### Альтернативные потоки
- Пустой заголовок: русскоязычная ошибка и повторный запрос в интерактивном CLI.
- Слишком длинный заголовок или тело: ошибка, хранилище не меняется.
- Пустое тело: ошибка и повторный запрос в интерактивном CLI.
- Ошибка записи: StorageError; старая полная версия данных сохраняется.

### Постусловие
В хранилище есть новая заметка, ID уникален, даты заданы; при ошибке старые данные сохранены.

**Связанные требования:** FR-001, UR-001; NFR-002 (надёжность), NFR-004 (русскоязычные ошибки).
**Модуль в коде:** `src/scenarios/add_note.py`
**Тесты:** `tests/test_add_note.py`
**Приоритет:** Must have.

## SC-002: Просмотр списка заметок

**User Story:** Как владелец заметок, я хочу увидеть все заметки, начиная с новых, чтобы быстро выбрать нужную запись.
**Актор:** Владелец заметок.
**Предусловие:** Хранилище доступно; пустое хранилище является допустимым состоянием.
**Триггер:** `note list`

### Основной поток
1. Загружаются все заметки.
2. Заметки сортируются по created_at, новые сверху.
3. Выводится таблица ID | Заголовок | Дата.

### Альтернативные потоки
- Пустое хранилище: «Заметок пока нет».
- Ошибка чтения или повреждённые данные: StorageError без изменения файла.

### Постусловие
Пользователь видит актуальный список в порядке убывания даты; данные не изменены.

**Связанные требования:** FR-002, UR-002; NFR-002 (надёжность), NFR-004 (русскоязычные ошибки).
**Модуль в коде:** `src/scenarios/list_notes.py`
**Тесты:** `tests/test_list_notes.py`
**Приоритет:** Must have.

## SC-003: Поиск заметок

**User Story:** Как владелец заметок, я хочу найти слово в заголовке или тексте без учёта регистра, чтобы быстро найти нужную информацию.
**Актор:** Владелец заметок.
**Предусловие:** Пользователь знает искомое слово; хранилище доступно.
**Триггер:** `note search --query ...`

### Основной поток
1. Принимается и проверяется непустой запрос.
2. Удаляются пробелы по краям запроса; применяется Unicode casefold.
3. Загружаются заметки и выбираются совпадения в title или body.
4. Результаты выводятся, новые сверху.

### Альтернативные потоки
- Пустой или пробельный запрос: ValidationError на русском.
- Нет совпадений: «Ничего не найдено».
- Ошибка чтения: StorageError.

### Постусловие
Показаны все совпадения; хранилище не меняется.

**Связанные требования:** FR-003, UR-003; NFR-002 (надёжность), NFR-004 (русскоязычные ошибки).
**Модуль в коде:** `src/scenarios/search_notes.py`
**Тесты:** `tests/test_search_notes.py`
**Приоритет:** Should have.

## SC-004: Редактирование заметки

**User Story:** Как владелец заметок, я хочу изменить заголовок или текст существующей заметки, чтобы поддерживать записи актуальными.
**Актор:** Владелец заметок.
**Предусловие:** Заметка с заданным ID существует.
**Триггер:** `note edit ID`

### Основной поток
1. Система находит заметку по ID.
2. Запрашивается новый заголовок; Enter сохраняет прежний.
3. Запрашивается новый текст; Enter сохраняет прежний.
4. Проверяются лимиты всех новых значений до записи.
5. Создаётся обновлённая заметка с теми же ID и created_at и новым updated_at.
6. Изменения сохраняются атомарно; показывается подтверждение.

### Альтернативные потоки
- ID не найден: NoteNotFoundError.
- Пустая строка при интерактивном вводе: соответствующее поле не меняется.
- Явно переданное пустое значение флага: ValidationError; для пропуска параметр не передаётся.
- Оба поля пропущены: возвращается прежняя заметка, запись и updated_at не меняются.
- Ошибка записи: StorageError; исходные данные не меняются.

### Постусловие
При изменении данных заметка обновлена; при отмене или ошибке исходные данные сохранены.

**Связанные требования:** FR-004, UR-004; NFR-002 (надёжность), NFR-004 (русскоязычные ошибки).
**Модуль в коде:** `src/scenarios/edit_note.py`
**Тесты:** `tests/test_edit_note.py`
**Приоритет:** Should have.

## SC-005: Удаление заметки

**User Story:** Как владелец заметок, я хочу удалить выбранную заметку после подтверждения, чтобы убрать ненужную запись и избежать случайного удаления.
**Актор:** Владелец заметок.
**Предусловие:** Заметка с заданным ID существует.
**Триггер:** `note delete ID`

### Основной поток
1. Система находит заметку по ID.
2. CLI запрашивает «Удалить заметку? [да/нет]:».
3. Пользователь подтверждает «да» или «yes».
4. Сценарий удаляет заметку и сохраняет остальные.
5. Выводится подтверждение.

### Альтернативные потоки
- Неизвестный ID: NoteNotFoundError до запроса подтверждения в CLI.
- Отказ, иной ответ или EOF: отмена без изменений.
- Ошибка записи: StorageError, сохранена старая версия данных.

### Постусловие
Подтверждённая заметка удалена; остальные записи не изменены. При отмене ничего не меняется.

**Связанные требования:** FR-005, UR-005; NFR-002 (надёжность), NFR-004 (русскоязычные ошибки).
**Модуль в коде:** `src/scenarios/delete_note.py`
**Тесты:** `tests/test_delete_note.py`
**Приоритет:** Could have.
